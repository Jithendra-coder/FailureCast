# FailureCast demo video

## Format

- 16:9 landscape, 1080p, about 70 seconds.
- Record the app at full browser width; keep the cursor deliberate and pause on the key evidence.
- Use captions for the numbers and labels. Keep the simulated-data disclosure on screen at the opening and close.
- Do not describe RUL estimates as certain failure dates or maintenance instructions.

## Storyboard and narration

| Time | Screen action | Voiceover |
| --- | --- | --- |
| 0:00–0:08 | Hold on the welcome page; let the trajectory lines draw in and show the research-demo label. | “FailureCast is a predictive-maintenance and MLOps research platform. It takes engine sensor history through validation, remaining-life forecasting, and controlled model monitoring.” |
| 0:08–0:18 | Select **Get started**. Let the fleet overview settle. | “The workspace brings the fleet, the active model, and the review queue into one place.” |
| 0:18–0:30 | Focus the priority asset and the RUL chart. Point out the threshold lines and current cycle. | “Here, ENG-006 has the fleet’s lowest estimate: 19.1 cycles at its latest observation. The thresholds make the review priority visible; the estimate is still a model output.” |
| 0:30–0:41 | Select **Inspect engine** and show the engine history. | “Engine detail lets a reviewer inspect the observed sensor trajectory alongside the remaining-life estimate.” |
| 0:41–0:51 | Return to the overview and show the model evidence and local sensitivity. | “Validation is reported on held-out engines. Local sensor sensitivity helps explain model behavior, but it is not a causal diagnosis.” |
| 0:51–1:02 | Show threshold alerts and dataset provenance. | “Alerts are review signals, and provenance stays attached to the selected dataset. This built-in workspace uses generated simulated telemetry—not live equipment readings or NASA source files.” |
| 1:02–1:10 | End on the overview and its three-step demo walkthrough. | “FailureCast makes the data, estimate, and model evidence easier to review in one reproducible workflow.” |

## Recording checklist

- Use the app’s current demo values only if they still match the visible workspace when recording.
- Keep the browser session free of unrelated tabs, notifications, credentials, and personal information.
- Confirm the intro and the **Get started** transition before recording.
- Re-read the dataset source label before stating where the data came from.
